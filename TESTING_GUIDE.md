# Інструкція з запуску юніт та інтеграційних тестів

Цей документ містить покрокову інструкцію щодо налаштування середовища, встановлення необхідних бібліотек та запуску автотестів для додатку авторизації та реєстрації (`sample_login_form`).

---

## 1. Вимоги до середовища (Prerequisites)

- **Node.js**: версія `>= 16.x`
- **npm**: версія `>= 8.x`

---

## 2. Встановлення залежностей

Для запуску тестів необхідні бібліотеки **Jest** (тестовий фреймворк) та **Supertest** (бібліотека для тестування HTTP-запитів Express).

Якщо ви запускаєте проект вперше або додаєте нові залежності, виконайте команду у цій папці:

```bash
npm install
```

Або для явного встановлення тестових залежностей:
```bash
npm install --save-dev jest supertest
```

---

## 3. Команди запуску тестів

Усі автотести знаходяться у директорії `tests/`.

### Основний запуск усіх тестів:
```bash
npm test
```

### Додаткові опції запуску:

- **Запуск у режимі спостереження (Watch mode):**
  ```bash
  npx jest --watch
  ```

- **Генерація звіту про покриття коду тестами (Coverage):**
  ```bash
  npx jest --coverage
  ```

- **Запуск конкретного файлу тестів:**
  ```bash
  npx jest tests/api.test.js
  ```

---

## 4. Опис тест-кейсив (`tests/api.test.js`)

Тестовий набір охоплює перевірку REST API сервісу:

1. **`GET /api/health`**
   - Перевірка працездатності сервера та отримання поточного двигуна БД (`sqlite` або `json`).

2. **`POST /api/signup`**
   - Успішна реєстрація нового користувача з коректними пошта/паролем (`201 Created`).
   - Перевірка обов'язковості полів Email та Password (`400 Bad Request`).
   - Валідація некоректного формату Email за regex (`400 Bad Request`).
   - Валідація максимально припустимої довжини Email (> 30 символів) (`400 Bad Request`).
   - Валідація недопустимих символів у паролі (`400 Bad Request`).
   - Захист від дублювання реєстрації (дублікат Email) (`409 Conflict`).

3. **`POST /api/login`**
   - Успішна авторизація раніше створеного користувача (`200 OK`).
   - Вхід із невірним паролем (`401 Unauthorized`).
   - Вхід для неіснуючого користувача (`401 Unauthorized`).
   - Перевірка валідації порожніх полів при вході (`400 Bad Request`).

4. **`GET /api/users`**
   - Перевірка отримання списку користувачів та коректного лічильника кількості.

---

## 5. Запуск додатка у звичайному режимі

Для запуску сервера для ручного тестування через браузер:

```bash
npm start
```
Сервер буде доступний за адресою: `http://localhost:3000`
