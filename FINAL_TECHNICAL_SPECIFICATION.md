# Ітогове Технічне Завдання (ТЗ) — Веб-застосунок входу та реєстрації "QA Manual 19.09.2024"

## 1. Загальні відомості про проєкт
- **Назва проєкту:** Веб-застосунок входу та реєстрації користувача (Login Form & Registration Module).
- **Брендінг та Логотип:** `QA Manual 19.09.2024`
- **Призначення:** Веб-модуль для авторизації, реєстрації та перевірки даних користувачів з підтримкою клієнтської і серверної валідації, збереженням даних у базі даних (SQLite / JSON) та перевіркою QA (Boundary Value Analysis / Equivalence Partitioning).
- **Технологічний стек:**
  - **Frontend:** HTML5, Vanilla CSS3 (Dark Theme), ES6+ JavaScript, Responsive Media Queries.
  - **Backend:** Node.js, Express.js (REST API).
  - **Database:** SQLite3 з універсальним фолбеком на вбудований JSON File DB (для підтримки cross-platform деплою на Render, Linux, Windows, macOS).

## 3. Функціональні вимоги до веб-інтерфейсу (Frontend)

### 3.1. Головна сторінка входу (`index.html`)
1. **Логотип:** Текст `QA Manual 19.09.2024`, вирівняний по центру, розмір `20px`, колір `#ffffff`.
2. **Поле `Email`:**
   - Поле типу `email`, обов'язкове для заповнення (`required`).
   - `maxlength="30"` (жорстке обмеження на рівні HTML та JavaScript).
   - Плейсхолдер: `Введіть Email`.
   - Маска формату: `a@b.c` (наприклад, `user@domain.com`).
   - Плавний ховер-ефект (зміна рамки з `#444` на `#666` та фону з `#3c3c3c` на `#444`).
   - Виведення помилок у червоний блок під полем (`#emailError`, колір `#ff3333`).
3. **Поле `Password`:**
   - Поле типу `password`, обов'язкове для заповнення (`required`).
   - `maxlength="30"`.
   - Плейсхолдер: `Введіть Password`.
   - Дозволені символи: латиниця (`a-z`, `A-Z`), цифри (`0-9`), а також символи `_`, `!`, `@`, `#`, `$`, `%`, `^`, `*`, `(`, `)`. Пробіли та кирилиця заборонені.
   - Інтерактивна кнопка перемикання видимості (`#togglePassword`):
     - Початковий стан: тип `password`, текст кнопки `Show`.
     - Натиснутий стан: тип `text`, текст кнопки `Hide`.
   - Виведення помилок у червоний блок під полем (`#passwordError`).
4. **Кнопка `Login` (`#loginBtn`):**
   - Колір фону `#0055ff`, колір тексту `#ffffff`, шрифт `15px bold`.
   - Ховер-ефект: зміна фону на `#0044cc`.
   - При натисканні: виконується клієнтська валідація полів та відправляється `POST /api/login`.
   - При успішному відповіді від сервера — зберігається сесія та здійснюється редирект у кабінет `PAGES/dashboard.html`.
5. **Посилання `Sign Up` (`#signUpLink`):**
   - Колір `#888888`.
   - Ховер-ефект: зміна кольору на `#0055ff` та підкреслення `underline`.
   - При натисканні: перехід на сторінку реєстрації `PAGES/signup.html`.

## 4. Специфікація Бекенду та Бази Даних (Backend REST API)

### 4.1. Схема Бази Даних (`users`)
Таблиця або структура запису користувача містить наступні поля:

| Поле | Тип даних | Обмеження | Опис |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY, AUTOINCREMENT | Унікальний ідентифікатор користувача |
| `email` | TEXT | UNIQUE, NOT NULL, MAX length 30 | Електронна пошта користувача |
| `password` | TEXT | NOT NULL, MAX length 30 | Пароль користувача |
| `created_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | Дата та час реєстрації |

### 4.2. Ендпоінти REST API

#### 1. `POST /api/signup`
- **Опис:** Реєстрація нового користувача та збереження в БД.
- **Request Body (JSON):**
  ```json
  {
    "email": "user@example.com",
    "password": "Password123!"
  }
  ```
- **Response Success (201 Created):**
  ```json
  {
    "success": true,
    "message": "Реєстрація успішна! Користувача збережено в базу даних.",
    "userId": 1
  }
  ```
- **Response Conflict (409 Conflict):**
  ```json
  {
    "success": false,
    "message": "Користувач з таким Email вже існує в базі даних."
  }
  ```

#### 2. `POST /api/login`
- **Опис:** Авторизація користувача за поштою та паролем.
- **Request Body (JSON):**
  ```json
  {
    "email": "user@example.com",
    "password": "Password123!"
  }
  ```
- **Response Success (200 OK):**
  ```json
  {
    "success": true,
    "message": "Вхід успішний!",
    "user": { "id": 1, "email": "user@example.com", "created_at": "2026-09-08T16:25:00.000Z" }
  }
  ```
- **Response Unauthorized (401 Unauthorized):**
  ```json
  {
    "success": false,
    "message": "Невірний Email або Password."
  }
  ```

#### 3. `GET /api/users`
- **Опис:** (QA Helper) Отримання списку зареєстрованих користувачів без відкриття паролів.
- **Response (200 OK):**
  ```json
  {
    "success": true,
    "count": 1,
    "dbEngine": "sqlite",
    "users": [
      { "id": 1, "email": "user@example.com", "created_at": "2026-09-08T16:25:00.000Z" }
    ]
  }
  ```

## 5. Тестова Матриця QA (Boundary Value Analysis & Equivalence Partitioning)

### 5.1. Класи Еквівалентності (Equivalence Partitioning)
- **Email:**
  - `Valid Class (Valid EP)`: Рядок формату `a@b.c`, довжиною від 5 до 30 символів, латинські літери/цифри.
  - `Invalid Class 1 (Format Error)`: Без `@`, без крапки в домені, з пробілами, кирилицею.
  - `Invalid Class 2 (Length Error)`: Порожній (0 симв.) або довжиною понад 30 символів.
- **Password:**
  - `Valid Class (Valid EP)`: Довжина від 1 до 30 символів, що містить тільки дозволені символи `[a-zA-Z0-9_!@#$%^&*()]`.
  - `Invalid Class 1 (Illegal Chars)`: Містить пробіли, кирилицю, недозволені спецсимволи (`~`, `<`, `>`, `,`, `"`, `'`, `/`, `\`).
  - `Invalid Class 2 (Length Error)`: Порожній (0 симв.) або довжиною понад 30 символів.

### 5.2. Матриця Граничних Значень (BVA Test Matrix)

| TC-ID | Поле / Параметр | Граничний стан (Boundary) | Вхідне значення (Input) | Очікуваний результат | Клас еквівалентності |
|:---:|---|---|---|---|:---:|
| **TC-01** | Email Length | `min - 1` (0 симв.) | `""` | Помилка: "Поле Email обов’язкове" | Invalid |
| **TC-02** | Email Length | `min` (5 симв.) | `"a@b.c"` | Успішна валідація | Valid |
| **TC-03** | Email Length | `nominal` (15 симв.) | `"test15@test.com"` | Успішна валідація | Valid |
| **TC-04** | Email Length | `max - 1` (29 симв.) | `"a1234567890123456789@domain.co"` | Успішна валідація | Valid |
| **TC-05** | Email Length | `max` (30 симв.) | `"a12345678901234567890@domain.co"` | Успішна валідація | Valid |
| **TC-06** | Email Length | `max + 1` (31 симв.) | `"a123456789012345678901@domain.co"` | Блокування ввода (maxlength=30) / Помилка довжини | Invalid |
| **TC-07** | Email Format | Invalid Format | `"invalidemail.com"` | Помилка: "Введіть коректний Email" | Invalid |
| **TC-08** | Email Format | Invalid Format | `"user@domain"` | Помилка: "Введіть коректний Email" | Invalid |
| **TC-09** | Password Length | `min - 1` (0 симв.) | `""` | Помилка: "Поле Password обов’язкове" | Invalid |
| **TC-10** | Password Length | `min` (1 симв.) | `"a"` | Успішна валідація | Valid |
| **TC-11** | Password Length | `max` (30 симв.) | `"A1!b2@C3#d4$E5%f6^G7*h8(I9)j0"` | Успішна валідація | Valid |
| **TC-12** | Password Chars | Special Allowed | `"_!@#$%^&*()"` | Успішна валідація | Valid |
| **TC-13** | Password Chars | Space (пробіл) | `"pass word"` | Помилка: "Пароль містить недопустимі символи" | Invalid |
| **TC-14** | Password Chars | Cyrillic (кирилиця) | `"Пароль123"` | Помилка: "Пароль містить недопустимі символи" | Invalid |
| **TC-15** | Password Mask | Toggle Button | Клік по `Show` | Текст паролю демаскується, кнопка змінюється на `Hide` | Valid |

## 7. Інструкція з Розгортання та Тестування

1. **Локальний запуск:**
   ```bash
   npm install
   npm start
   ```
   Доступ у браузері: `http://localhost:3000`

2. **Деплой на Render.com / Cloud VPS:**
   - Репозиторій містить `.gitignore` з виключенням `node_modules` для уникнення помилок сумісності нативних модулів на Linux.
   - Сервер працює з безпомилковим автоперемиканням `sqlite3` $\rightarrow$ `database.json`.
