Ітогове Технічне Завдання (ТЗ) — Веб-застосунок входу та реєстрації "QA Manual 19.09.2024"

1. Загальні відомості про проєкт

  • Назва проєкту: Веб-застосунок входу та реєстрації користувача (Login Form & Registration Module).
  • Брендінг та Логотип: QA Manual 19.09.2024
  • Призначення: Веб-модуль для авторизації, реєстрації та перевірки даних користувачів з підтримкою клієнтської і серверної валідації, збереженням даних у базі даних (SQLite / JSON) та перевіркою QA (Boundary Value Analysis / Equivalence Partitioning).
  • Технологічний стек:
  • Frontend: HTML5, Vanilla CSS3 (Dark Theme), ES6+ JavaScript, Responsive Media Queries.
  • Backend: Node.js, Express.js (REST API).
  • Database: SQLite3 з універсальним фолбеком на вбудований JSON File DB (для підтримки cross-platform деплою на Render, Linux, Windows, macOS).

4. Специфікація Бекенду та Бази Даних (Backend REST API)

4.1. Схема Бази Даних (users)

Таблиця або структура запису користувача містить наступні поля:

Поле Тип даних Обмеження Опис
id INTEGER PRIMARY KEY, AUTOINCREMENT Унікальний ідентифікатор користувача
email TEXT UNIQUE, NOT NULL, MAX length 30 Електронна пошта користувача
password TEXT NOT NULL, MAX length 30 Пароль користувача
created_at DATETIME DEFAULT CURRENT_TIMESTAMP Дата та час реєстрації

4.2. Ендпоінти REST API

1. POST /api/signup

  • Опис: Реєстрація нового користувача та збереження в БД.
  • Request Body (JSON): json { "email": "user@example.com", "password": "Password123!" }
  • Response Success (201 Created): json { "success": true, "message": "Реєстрація успішна! Користувача збережено в базу даних.", "userId": 1 }
  • Response Conflict (409 Conflict): json { "success": false, "message": "Користувач з таким Email вже існує в базі даних." }

2. POST /api/login

  • Опис: Авторизація користувача за поштою та паролем.
  • Request Body (JSON): json { "email": "user@example.com", "password": "Password123!" }
  • Response Success (200 OK): json { "success": true, "message": "Вхід успішний!", "user": { "id": 1, "email": "user@example.com", "created_at": "2026-09-08T16:25:00.000Z" } }
  • Response Unauthorized (401 Unauthorized): json { "success": false, "message": "Невірний Email або Password." }

3. GET /api/users

  • Опис: (QA Helper) Отримання списку зареєстрованих користувачів без відкриття паролів.
  • Response (200 OK): json { "success": true, "count": 1, "dbEngine": "sqlite", "users": [ { "id": 1, "email": "user@example.com", "created_at": "2026-09-08T16:25:00.000Z" } ] }

5. Тестова Матриця QA (Boundary Value Analysis & Equivalence Partitioning)

5.1. Класи Еквівалентності (Equivalence Partitioning)

  • Email:
  • Valid Class (Valid EP): Рядок формату a@b.c, довжиною від 5 до 30 символів, латинські літери/цифри.
  • Invalid Class 1 (Format Error): Без @, без крапки в домені, з пробілами, кирилицею.
  • Invalid Class 2 (Length Error): Порожній (0 симв.) або довжиною понад 30 символів.
  • Password:
  • Valid Class (Valid EP): Довжина від 1 до 30 символів, що містить тільки дозволені символи [a-zA-Z0-9_!@#$%^&*()].
  • Invalid Class 1 (Illegal Chars): Містить пробіли, кирилицю, недозволені спецсимволи (~, <, >, ,, ", ', /, \).
  • Invalid Class 2 (Length Error): Порожній (0 симв.) або довжиною понад 30 символів.
